# 2.3.0 → 3.0 regression sweep

**Date:** 2026-07-04
**Status:** Complete. Two regressions found and fixed in `3.0.0-alpha.4`; two items
left as explicit decisions (below).
**Context:** 2.3.0 (PR [#43](https://github.com/iternio/ovms-link/pull/43)) was
field-validated over two weeks. 3.0 is a modular, change-based redesign that **forked
before** some 2.3.0 fixes landed, so this sweep checks each validated 2.3.0 behavior
against the 3.0 modules before building further on the baseline.

## Method

For each behavior in the 2.3.0 changelog, locate the equivalent in `lib/abrp/*.js`
and confirm it is present, superseded, or lost. Confirmed the fork point with
`git merge-base --is-ancestor`.

## Findings

| 2.3.0 behavior | 3.0 status | Evidence |
| --- | --- | --- |
| Bulk queue + GPS-time gating | ✅ intact | `events.js` `checkTime` + `send()` hard-guard on `_isTimeValid` |
| Clear queue only on HTTP 200 **and** `status:"ok"` | ✅ intact | `telemetry.js` `sendBulkTelemetry` done-handler |
| In-flight batch removed by identity | ✅ intact | `queue.js` `removeTelemetryBatch` (indexOf, not positional splice) |
| Overflow can't drop never-sent points | ✅ intact | identity removal + pre-flight `snapshot` |
| `capacity` / `soe` / hvac_power-via-override / `v.t.pressure` vector / Nissan Leaf range | ✅ intact | `metrics.js` `metricMap` + `overrideMetricMap` |
| **Charge-power deadband (DCFC flood)** | ❌ **regressed → fixed** | `queue.js` rounded power to 0.1 kW; any change queued |
| **Session: `charge.stop` must not kill sampler mid-drive** | ❌ **regressed → fixed** | `charge.stop`→`callbackVehicleOff`→`unsubscribe(ticker.1)` |
| **Session: overlap must not double-subscribe** | ❌ **regressed → fixed** | `charge.start`→`callbackVehicleOn` subscribed unconditionally |
| **Session: `send(0)/send(1)` teardown symmetric** | ❌ **regressed → fixed** | teardown didn't unsubscribe `ticker.10` / `vehicle.type.set` |
| Session: cold-boot resume | ✅ intact | independently re-added on 3.0 (`75fbd72`) |
| AC-charge cadence fix | ✅ moot by design | 3.0 removed state-adaptive cadence, so the mis-selection can't occur |
| Median power/speed smoothing while driving | ⚠️ removed by design | alpha.1 sends instantaneous; **decision below** |
| Per-point delta encoding (#41) | ✅ bonus (new in 3.0) | `telemetry.js` `deltaEncode`, full-first-point-per-batch |

## Root cause

The 2.3.0 session commit (`5b00c66`) and deadband commit (`073b999`) are **not**
ancestors of 3.0 HEAD — 3.0 forked before them. The data-integrity and metrics fixes
predate the fork point (or were re-derived); the session + deadband work was not, and
3.0 had **no charge/drive overlap tests**, so the loss was invisible. Real-world
impact of the session regression: charge overnight → get in → unplug → drive to work
sent **no telemetry for the whole commute** (sampler torn down on the unplug's
`charge.stop`, plus a spurious parked bookend).

## Fixes applied (`3.0.0-alpha.4`, TDD)

- **Session** (`events.js`): `isSampling` flag + `isVehicleActive()` +
  `updateSamplingState()`; all four events route through it; symmetric teardown.
- **Deadband** (`queue.js` + `constants.js`): `withinChargeDeadband()` skips the
  `power` field in `changedVsLastQueued` while charging when the move is
  `< CHARGE_POWER_DELTA_KW` vs the last queued point.
- **Tests:** `lib/abrp.test.js` "charge/drive overlap state machine (bundle)" (4
  cases) and `queue.test.js` deadband case. Full suite 83/83, ESLint clean.

## Left as explicit decisions

1. **Median smoothing while driving** — 3.0 removed it (sends instantaneous rounded
   power/speed). 2.3.0 restored it. This is a data-quality choice, not a bug: decide
   whether ABRP wants smoothed driving power or the raw sampled value. Not reinstated
   here.
2. **`DEBUG: true` in `constants.js`** — expected for an alpha, but must be flipped to
   `false` before any 3.0 release (per the standing pre-release checklist).
