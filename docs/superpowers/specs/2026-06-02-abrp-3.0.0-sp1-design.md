# ABRP 3.0.0 — SP1: Packaging foundation + cert self-healing — Design

**Date:** 2026-06-02
**Author:** kezarjg (with Claude Code)
**Status:** Approved for planning
**Branch:** `feature/abrp-3.0.0`
**Parent:** `docs/superpowers/specs/2026-06-02-abrp-3.0.0-scope-design.md` (3.0.0 scope)

SP1 is the **delivery + structure + cert-robustness foundation** for 3.0.0.
Everything else (SP2 plan API, SP3 web UI) depends on it. It ships as
`3.0.0-alpha.1`, delivered as three ordered work-streams (each its own
implementation plan).

## Goal

Turn the hand-copied single-file script into an **installable, self-updating,
modular OVMS plugin** whose TLS "just works." No new telemetry features — pure
delivery, structure, and robustness, so it is cleanly testable against the
existing behavior.

## Scope

**In:** module split + a build/bundler; OVMS plugin packaging (manifest +
GitHub-Pages repo + `plugin install`/`update`); retire the manual hand-copy path;
cert self-healing.

**Out (other sub-projects / deferred):** `planning.js` and notifications (SP2);
web UI (SP3); OAuth2; auto-limit charging.

## Work-streams (ordered)

| # | Work-stream | Milestone | Behavior change? |
| --- | --- | --- | --- |
| WS1 | Module split + bundler | 3.0.0-alpha.1a | **No** (pure refactor) |
| WS2 | Plugin packaging + GitHub Pages distribution | 3.0.0-alpha.1b | No (delivery only) |
| WS3 | Cert self-healing | 3.0.0-alpha.1c | Yes (new robustness feature) |

Order rationale: establish the modular structure + build first (under the existing
test suite, no behavior change), then package the bundled artifact, then add
cert-healing into the new structure. WS3 is independent of WS1/WS2 and could move
earlier, but slots cleanly into `certs.js`/`iternio.js` last.

## WS1 — Module split + bundler

### Modules (`lib/abrp/*.js`)

Split today's `abrp.js` (~870 lines) into focused modules. `planning.js` is **not**
part of SP1 (SP2). Each module owns its state and exposes accessors (extends the
existing `__test` seam pattern); no god-`state.js`.

| Module | Responsibility |
| --- | --- |
| `util.js` | `logger`, `timestamp`, `clone`, `round`, `medianPowerMetrics` |
| `config.js` | token state, `validateUsrAbrpConfig`, reset |
| `metrics.js` | `metricMap`, `overrideMetricMap`, `isOvmsMetricSupported`, `getOVMSMetric`, `createTelemetry` |
| `queue.js` | queue/collected/lastQueued state, `queueTelemetry*`, `removeTelemetry`/`removeTelemetryBatch`, `isSignificantTelemetryChange`, `calculateMaxElapsedDuration` |
| `iternio.js` | shared transport: URL/key/token, `HTTP.Request` wrapper, `isApiOk`, cert-heal-on-fail hook (WS3) |
| `telemetry.js` | `sendTelemetry`, `createBulkPost`, `sendBulkTelemetry`, `isSending` |
| `certs.js` | bundled non-embedded CA PEMs + `detectCertError`/`healCerts` (WS3) |
| `events.js` | `subscribe`/`unsubscribe` + subscriptions state, vehicle callbacks, `manageVehicleStateEvents`, `checkTime`, `send` start/stop, `isActive`/`isTimeValid` |
| `abrp.js` *(entry)* | public commands (`info`, `onetime`, `send`, `resetConfig`), startup wiring, `module.exports` |

- **Inter-module requires use native relative ids** (`require('./queue')`), resolved
  at **build time** by the bundler — so the delivered file has no `require`s, and
  OVMS's no-relative-require / `plugin/` prefix limitations never apply.
- Modules are CommonJS (`module.exports`), matching Duktape.

### Bundler (`build.js`, dependency-free)

- A ~60-line Node script: reads the `lib/abrp/*` modules, wraps each in a minimal
  CommonJS shim (a tiny `require`/`module.exports` registry resolved in dependency
  order from the entry), and emits a single **Duktape-safe** `dist/abrp.js`.
- **Output guardrail:** the build runs a post-bundle assertion that the emitted file
  contains no `=>`, template literals, or object spread in code (the same check
  used on `lib/abrp.js` today). Source modules keep the ES2015 / `var`+`function`
  style.
- **Rejected alternative:** esbuild/rollup — their CJS interop helpers emit arrow
  functions / modern syntax even at `--target=es2015`, which the Duktape guardrail
  forbids and whose support on the target Duktape we can't guarantee. The custom
  concatenator gives full control of emitted syntax with zero toolchain risk.

### Testing

- Jest tests each module in isolation using **native relative `require`** (no
  `moduleNameMapper`). The existing 26 tests migrate to the relevant module specs.
- A **bundle smoke test**: build `dist/abrp.js`, `require` it under Jest with the
  host-global stubs, and assert the public surface (`info`/`onetime`/`send`/
  `resetConfig` + `__test`) behaves identically — proving the bundle equals the sum
  of its modules.

### Acceptance (WS1)

No behavior change: the bundled `dist/abrp.js` passes the full suite and the smoke
test; ESLint clean; output Duktape-safe. The single-file `lib/abrp.js` is replaced
by `lib/abrp/*` + `dist/abrp.js`.

## WS2 — Plugin packaging + GitHub Pages distribution

### Manifest (`abrp.json`)

- One `module` element → the bundled `abrp.js` (so a single global `abrp`;
  `script eval abrp.info()` keeps working).
- `name: abrp`, `version` tracks the plugin `VERSION`, `maintainer`, `description`,
  `group`, `prerequisites: ["ovms>=3.3.004"]`.

### Distribution (GitHub Pages)

- A Pages site (served from this repo) hosts:
  - `plugins.json` (repo index, lists `abrp`)
  - `abrp/abrp.js` (bundled deliverable)
  - `abrp/abrp.json` (manifest / `EL_JSON` element)
- The **build publishes** these into the Pages directory, so a release is
  "rebuild + push."
- **TLS:** GitHub Pages chains Let's Encrypt → **ISRG Root X1**, which OVMS embeds
  in firmware — so `plugin install` from GitHub is trusted out of the box (no cert
  setup, no dependency on WS3).
- The exact Pages URL/org (`<org>.github.io/ovms-link`) is settled at
  implementation; an `openvehicles` default-repo submission is a later option.

### Install/update flow

- `plugin repo install abrp https://<pages-url>/` → `plugin install abrp` →
  `plugin update`. The plugin auto-loads (`require("plugin/abrp/abrp")`); **no
  `ovmsmain.js`** is shipped or edited.
- README rewritten: replace the hand-copy section with the plugin flow; keep the
  token-config step (config-page UI is SP3).

### Acceptance (WS2)

`plugin install abrp` from the Pages repo installs and runs the bundled plugin on a
real module; `plugin update` upgrades it; the manual-copy instructions are retired.

## WS3 — Cert self-healing

### Bundled certs (`certs.js`)

Bundle **only non-embedded** CAs. Against the OVMS firmware-embedded roots
(`amazon_root_ca1`, `isrg_x1`, `digicert_global`, `digicert_g2`,
`baltimore_cybertrust`, `starfield_class2`, `usertrust`):

- `amazon` (2.x set) → embedded → **skip**
- `isrgrootx1` → embedded (`isrg_x1`) → **skip**
- GoDaddy `gdroot-g2` → not embedded → **bundle**
- `root-r1` → identify its root at implementation; bundle only if not embedded.

The exact bundled set is pinned during implementation by checking each cert's root
against the embedded list.

### Detect → heal

- **Detect:** in `iternio.js`'s `fail` handler, classify the error — a TLS/X509
  (mbedTLS) signature, especially when no send has succeeded this session, indicates
  a probable missing/untrusted CA (vs. a plain network error).
- **Heal (guarded, once/session):** `VFS.Save` the bundled PEM(s) to
  `/store/trustedca/abrp-*.crt` → on success → `OvmsCommand.Exec("tls trust reload")`.
  A `certHealAttempted` flag prevents looping on genuine outages.
- **Retry is free:** the 2.3.x at-least-once semantics keep the failed batch queued,
  so the next `ticker.10` retries over the now-fixed trust store. (Optional: verify
  with `tls trust list` — decided at implementation.)

### Safety

Certs are **bundled/pinned** in the plugin, never fetched over the network (fixing
trust via an untrusted connection would be a chicken-and-egg hole). Healing is
**reactive-only** — the trust store is touched only on a detected failure.

### Testing

With stubbed `HTTP`/`VFS`/`OvmsCommand`: a TLS-class `fail` triggers exactly one
`VFS.Save` + `tls trust reload`; a second failure does **not** re-heal (guard); a
plain network error does **not** trigger a heal.

### Acceptance (WS3)

On a module missing the required CA, a failed send auto-installs the bundled CA and
the next tick succeeds — with no manual `tls trust` steps.

## Plan-time decisions (resolved in writing-plans / implementation)

- Exact bundled-cert set (identify `root-r1`'s root; confirm against embedded list).
- Bundler module-ordering / shim details; whether `cadence` splits out of `queue`.
- GitHub Pages org/URL; whether to also submit to `openvehicles`.
- Whether the heal verifies via `tls trust list`.

## Risks

- **Bundler correctness/Duktape-safety** — mitigated by the post-bundle syntax
  assertion + the bundle smoke test proving behavioral equivalence.
- **Migration** — plugin-only retires manual install; clear release notes; the
  GitHub-Pages repo + `openvehicles` redirect ease discovery.
- **Cert-detection precision** — a misclassified network error costs one harmless
  cert write + reload per session; the once/session guard bounds it.
- **WS1 is a large refactor** — gated by "no behavior change" + the full existing
  suite; do WS1 fully before WS2/WS3.
