# ABRP plugin 2.3.0 — Refactor completion design

Date: 2026-06-01
Author: kezarjg (with Claude Code)
Status: Approved for planning

## Background

`kezarjg/ovms-link` is a fork of the official `iternio/ovms-link` ABRP/Iternio
OVMS plugin. The local `dev` branch carries an unfinished refactor tagged
`2.2.0-beta` that the author began and never completed or pushed upstream. The
branches have diverged from a common base (`d3842a5`):

- **Our `dev`** added a telemetry **bulk-upload pipeline**: a queue
  (`telemetryToSend`, `MAX_TELEMETRY_QUEUE_SIZE`), bulk POST to `/1/tlm/bulk`,
  GPS-time gating (`checkTime`), token-tracking `subscribe`/`unsubscribe`
  wrappers, and a `vehicle.type.set` → `overrideMetricMap` callback.
- **`upstream/dev`** shipped a plain `2.2.0` (metricMap only, single-point
  `/1/tlm/send`) and added artifacts our branch lacks: a `trustedca/` folder of
  CA certificates (Amazon, ISRG Root X1, GoDaddy G2, root-r1) required for TLS to
  `api.iternio.com`, an updated `README.md` install flow, and an `ovmsmain.js`
  tweak.

Metric keys and vehicle-specific cases (`KS`, `NL`, `SUBSOL`, `TOYBZ4X`) are
**identical** between the two `abrp.js` files; ours is a strict superset of
upstream's logic. The only upstream-unique source code is the `omitNil` helper.

### Runtime constraints (unchanged, inviolable)

The plugin runs in OVMS's **Duktape** engine (ECMAScript 2015, `var`-style, host
globals `HTTP`/`OvmsConfig`/`OvmsMetrics`/`OvmsNotify`/`PubSub`/`performance`/`print`
injected, not imported). The product is **hand-copied file-by-file** into the OVMS
web editor, so the deliverable must remain a single `lib/abrp.js` (plus
`ovmsmain.js` and the `trustedca/` certs). No bundler/build step.

## Goals

1. Bring the branch onto a current upstream base, gaining the CA certs and README.
2. Make the code testable and complete the test suite.
3. Fix the defects found while resuming the work.
4. Ship as `2.3.0`, positioned for an eventual clean PR to upstream.

## Non-goals

- Splitting `abrp.js` into multiple deliverable files (rejected: install UX).
- Adding a build/bundler toolchain (rejected: keeps repo build-free).
- Setting up CI (noted as optional follow-up, out of scope).
- Unrelated refactoring beyond the four findings below.

## Assessment findings (the work to do)

Found while auditing the beta pipeline:

1. **🔴 Telemetry data loss on concurrent flush.** `createBulkPost()` sets
   `tlm_list: telemetryToSend` (the *live* array). `sendBulkTelemetry()` runs on
   `ticker.10` (8s timeout) and on success removes
   `bulkPost.data[0].tlm_list.length` items from the front. Since `tlm_list` is the
   same reference, the count is read at *completion* time — if `ticker.1` appended
   during the request, more items are spliced than were actually sent, dropping
   unsent points. No in-flight guard exists, so a slow request overlapping the next
   `ticker.10` can also double-send. (An `isSending` flag existed in commit
   `159a621` but was removed in the "stop retrying" change.)

2. **🟠 Advertised metrics never populate.** `capacity`, `soe`, and `hvac_power`
   have empty/absent `requiredMetrics` and no `metric()` function, so
   `getOVMSMetric()` always returns `[false, null]` — they are never sent, despite
   the CHANGELOG listing them as added.

3. **🟠 Median-smoothing path is dead in the default config.** With
   `BANDWIDTH_SAVER = false` (default), `queueTelemetryIfNecessary()` sends every
   `METRIC_POLL_RATE_DRIVING` (5s) and returns *before* the `collectedMetrics`
   collection runs. So `medianPowerMetrics()` — the best-tested function — never
   executes, and the "median power over 1s samples" calibration feature (CHANGELOG
   2.0) is effectively disabled.

4. **🟡 Doc/comment mismatches.** `createBulkPost()`'s comment says "up to the
   first 10 elements" but it sends the entire queue (the 10-cap from `a42218b` was
   reverted). Other comments and CHANGELOG metric claims are stale.

5. **🟡 Test suite cannot run.** `require('./abrp')` executes module-load side
   effects — the line-21 `OvmsConfig.GetValues` token read, `overrideMetricMap()`,
   and `subscribe('ticker.1', …)` — which throw without OVMS globals. The test also
   imports `omitNil`, dropped in the refactor. Result: zero tests execute.

## Approach: three phases

Chosen for low-risk front-loading and to ensure every logic change lands under a
regression test. Phase 1 changes no logic; Phase 2 changes no behavior; Phase 3
is test-driven.

### Phase 1 — Additive upstream integration (no logic change)

Merge `upstream/dev` into a fresh working branch. Conflict resolution:

| Path | Resolution |
| --- | --- |
| `lib/abrp.js` | **ours** (strict superset) |
| `trustedca/*` | **upstream** (new files, auto-merge) |
| `README.md` | **upstream** (improved install flow + cert steps) |
| `ovmsmain.js` | **upstream** (their added line) |
| `CHANGELOG.md` | combine both histories |

Then set `VERSION` to `2.3.0` (drop `-beta`). End state: current code on a current
base, certs present, zero behavior change. Verify `git diff` of `abrp.js` logic vs
our pre-merge `dev` is empty (only the version string changes).

Note: `omitNil` is intentionally **not** carried into `abrp.js` — it is unused by
the pipeline and its test is being dropped (see Phase 2).

### Phase 2 — Test harness (no behavior change)

- **Guard module-load side effects** so `require()` is side-effect-free off-device:
  - Token read: `var user_token = (typeof OvmsConfig !== 'undefined') ?
    OvmsConfig.GetValues('usr', 'abrp.').user_token : undefined`
  - Auto-start block at file bottom:
    `if (typeof OvmsConfig !== 'undefined' && typeof PubSub !== 'undefined') {
    overrideMetricMap(); subscribe('ticker.1', checkTime); }`
- **Export the now-critical pure functions** for testing, alongside existing
  `round`/`medianPowerMetrics`: `isSignificantTelemetryChange`,
  `calculateMaxElapsedDuration`, `createBulkPost`, and the per-metric `metric()`
  computations (exercised via small `OvmsMetrics` stubs in the specific tests that
  need them).
- **Drop the `omitNil` test** from `lib/arbp.test.js`.
- Keep the single deliverable file; install UX unchanged.

### Phase 3 — Bug fixes, test-driven

Each fix is written failing-test → fix → green.

1. **Data-loss concurrency (🔴).**
   - Introduce `MAX_BULK_BATCH_SIZE` (restores the bounded batch).
   - Capture a fixed batch at send time:
     `var batch = telemetryToSend.slice(0, MAX_BULK_BATCH_SIZE)`; build the post
     from `batch`; on HTTP success call `removeTelemetry(batch.length)`. Because we
     only append to the tail and remove from the front, removing `batch.length`
     from the front stays correct even if appends happened mid-flight.
   - Add an `isSending` in-flight guard: set true at request start, cleared in both
     `done` and `fail`; `sendBulkTelemetry()` early-returns if already sending.
   - Update the `createBulkPost` comment to match the bounded batch.
   - *Tests:* removal count is independent of concurrent appends; re-entry is
     blocked while a request is in flight (mocked `HTTP.Request`).

2. **Unpopulated metrics (🟠).** For `capacity`, `soe`, `hvac_power`: where an OVMS
   source metric exists, wire it through the `metricMap` `metric()` +
   `requiredMetrics` pattern (e.g. `soe` derivable from `soc × capacity`); where
   OVMS has no source, **remove the entry and correct the CHANGELOG**. The exact
   source-metric determination is an implementation step; each `metric()` function
   is pure and gets a unit test.

3. **Dead median path (🟠).** Restructure `queueTelemetryIfNecessary()` so
   high-frequency `collectedMetrics` collection runs whenever the vehicle is not
   parked (not gated behind `BANDWIDTH_SAVER`), and the median is applied when
   telemetry is queued. Restores the calibration feature and puts
   `medianPowerMetrics()` back on the live path.
   - *Tests:* collection populates in the default config; median is applied to
     queued telemetry.

4. **Doc/comment mismatches (🟡).** Fix the `createBulkPost` comment, audit other
   stale comments, reconcile CHANGELOG metric claims with what actually sends.

## Testing strategy

- **Automated (Jest):** pure-logic unit tests plus the four regression tests
  above. Adding a GitHub Action to run them is an optional follow-up, out of scope.
- **Manual on-vehicle validation (author-run checklist):**
  1. Install updated `abrp.js`, `ovmsmain.js`, and all `trustedca/` certs; run
     `tls trust reload` and confirm `tls trust list` shows the new roots.
  2. Reload the JS engine; confirm the `ABRP::started` notification.
  3. `script eval abrp.info()` — verify telemetry values, including any newly
     wired metrics (`soe`/`capacity`), and the `2.3.0` version string.
  4. `script eval abrp.onetime()` — confirm a single send succeeds over TLS
     (validates the new certs).
  5. `script eval abrp.send(1)` — drive/charge and confirm the queue drains over
     `ticker.10`, SOC/charging/parked changes trigger prompt sends, and no
     telemetry is lost across overlapping flushes.
  6. `script eval abrp.send(0)` — confirm clean stop and unsubscribe.

## Versioning & upstream PR

- `VERSION = '2.3.0'`; add a `2.3.0` CHANGELOG entry covering the bulk pipeline,
  GPS-time gating, token-tracking subscriptions, and the four fixes.
- The eventual upstream PR is raised from the clean `2.3.0` branch; lineage stays
  sane because Phase 1 was a real merge of `upstream/dev`.

## Risks

- **Merge resolution error in Phase 1** could silently revert pipeline logic.
  Mitigation: assert the post-merge `abrp.js` logic diff vs pre-merge `dev` is
  empty except the version string.
- **Metric source unknown (finding 2)** — some of `capacity`/`soe`/`hvac_power`
  may have no OVMS source on the author's vehicles; resolution is wire-or-remove,
  not invent.
- **On-vehicle behavior** cannot be unit-tested; the manual checklist is the only
  validation for real `HTTP`/`OvmsMetrics` interaction and TLS connectivity.
